# Rules for Claude Code in this repository

This is the research site for the **Status Saver** app (app name Status Flow, package `com.statussaver.videosaver.downloadstatus.storysaver`). It follows the house rules in `CONTRIBUTING.md` — *GitHub Repository Handling Guidelines*, the same rules as every other repository under this GitHub account. Everything below is the short version for this repository; read `CONTRIBUTING.md` before a first change.

`docs/knowledge.md` loads with this file. Answer from it whenever you can.

## Layout

```
tabs/<NN>-<name>/index.html   one page per tab, with its own images
  01-status-saver/            the product dossier (8 sections), its gfx/ and shots/
assets/nav.js                 the tab bar; its TABS list sets the tabs and their order
assets/bar.css                tab-bar styling for tabs that bring their own design (tab 01 does)
docs/knowledge.md             key facts and decisions - hand-written
docs/README.md                documentation guide - hand-written
docs/tabs/, docs/backend/, docs/code-map.md, docs/data-dictionary.md, docs/research-index.md
                              GENERATED by GitHub after every push: never edit by hand
research/                     the sources behind the numbers
tools/export-docs.js          the generator the "Update docs" workflow runs: never run it yourself
```

`assets/data.js` is **generated** by `research/aso-pipeline/build.ps1` from the JSON sources next to it — edit `listing.json` (the copy and written sections) or the other sources and re-run `build.ps1`, never edit the payload. `build.ps1` touches no network. The scrapers beside it (`collect.ps1`, `analyze.ps1`, `graphics.ps1`, `features.ps1`, `titlecheck.ps1`) must not be re-run; `brandcheck.ps1` is an offline analyser and is safe. Tab 01 is a self-contained page and reads neither `data.js` nor `app.js`.

## Before anything

1. `git pull --rebase`.
2. Answer from `docs/knowledge.md`. Open more only when the request needs it:
   - what a tab says → `docs/tabs/<tab>.md`
   - which file, line or function produces a section → `docs/code-map.md`
   - how a tab works, with its full code → `docs/backend/<tab>.md` or `/backend <tab>` (large: only for code questions)
   - how the data was collected → `docs/backend/research.md`, `docs/research-index.md`, `research/README.md`

## Changing wording or numbers

Find the text in `docs/tabs/<tab>.md`, find the place to edit in `docs/code-map.md`, edit that one place — for tab 01 that is `tabs/01-status-saver/index.html`. Correct `docs/knowledge.md` if a fact changed. No scripts, no builds, no browser checks, no doc export: GitHub regenerates the docs after the push.

## Changing how a tab works, or adding a tab

- Code or data change: load the tab's backend first, edit, then open the page from disk in a browser and check the console. Only code changes need that check.
- New tab: create `tabs/<NN>-<name>/index.html` from an existing tab's skeleton (keep the `noindex` meta and the `nav.js` line), keep its images in its own folder, add one line to `TABS` in `assets/nav.js` and one line to `docs/knowledge.md`. Never renumber existing tabs.
- Importing a Claude artifact: load `assets/bar.css` instead of `site.css`, drop any claude.ai frame script, and put the artifact's files in the tab folder. Tab 01 is the worked example.

## Content rules

- Public repository. Never commit keys, tokens, ad identifiers (including AdMob app and unit IDs), `google-services.json`, signing keys, `.aab`/`.apk` builds, Play Console exports or personal email addresses. The AdMob app ID from the source artifact was deliberately removed from tab 01 — do not put it back.
- **WhatsApp may be named in the full description only** — to say what the app reads, and nothing more. Not in the title, not in the short description (decision of 24 Sep 2026: Play's test is confusion and the house title check passes, but WhatsApp's own brand guidelines forbid combining the name with generic terms, Meta runs an enforcement team, Google's trademark enforcement is complaint-driven rather than proactive, and 0 of the 20 largest apps on this shelf put the brand in the title). Keep the WhatsApp mark out of the icon and store art, never say or imply "official" or "affiliated", and keep the disclaimer in the description. Those are what make the naming defensible — do not drop any of them.
- Names that stay out of the copy, each for its own reason: platforms the app **cannot read** (Instagram, Facebook, TikTok) because the claim would be false; modified clients (GB/FM/YO WhatsApp) because Play bans facilitating them; another developer's app name because that is impersonation. A phrase is judged by why it could not be used, never by whether a product name appears in it.
- A borderline listing term needs a live Google Play title check (5+ third-party titles, 2+ with 1M+ installs, oldest 3+ years), run and dated in `docs/knowledge.md`. Never report a check as passed unless it was run — and never block a term as a "brand" without running it either. Run it with `research/aso-pipeline/brandcheck.ps1`.
- Claims must match what the app does, including that it shows ads.
- Every page keeps `<meta name="robots" content="noindex">`.
- Change only what was asked; check the author before rewriting someone else's section.

## Publishing

`git pull --rebase` → `git add` only what changed → `git commit -m "<Tab>: <what changed>"` → `git push`. Never force-push. The site updates about a minute later, then the "Update docs" workflow regenerates `docs/` and commits it, so pull again before the next change.
